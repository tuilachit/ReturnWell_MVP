# External handover — local implementation

The GP and assigned practitioner now share a participant-only handover panel. It displays the **referring practice's** independently reviewed A6 contact, not a receiving clinic phone scraped from the web. If that contact has not been reviewed, the panel says so and directs participants to their existing ReturnWell support channel. It never falls back to account metadata or an unreviewed email address.

Only current active members of the referring practice or the currently authorised assigned practitioner can read it. Operator status alone is insufficient; suspended/revoked and pending-onboarding practitioner access is denied. The response contains status, practice name, reviewed work phone/instructions/date and next action — no clinical summary, patient reference, credential evidence or email address.

Acceptance says to agree an approved external handover channel. Appointments, identifying patient information and payments remain outside ReturnWell. A3 already requires an explicit confirmation before recording `handover_completed`; this panel never updates a referral or infers a booking/consultation.

Instructions render as text. Only validated HTTPS links without credentials/query/fragment are clickable, using a no-referrer/no-opener link. Phone links contain only a validated telephone number, never a message body. Contacts and permissions are fetched again on focus; stale responses cannot populate a different referral/version.

Local evidence: missing-feature and stale-contact browser regressions were observed and corrected; participant/outsider/operator/revocation/status cases are covered in the database suite. Shared-handler browser journeys run against local Auth/PostgREST, not a hosted Edge Function or received mailbox. A pilot clinician still needs to validate that this contact direction and external handover procedure work in practice before D7. No production change, real referral, patient data or external send was made.
