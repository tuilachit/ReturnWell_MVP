# ReturnWell Directory and Matching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the two-profession assumption with safe allied-health coverage and make matching useful, explainable and scalable.

**Architecture:** One reviewed catalogue drives fields, credential protocols and display labels. Add generic credentials alongside legacy AHPRA data, use server-authoritative eligibility, and introduce explicit query projections/pagination. Geography is optional licensed reference data, not a dependency on a paid maps service.

**Tech Stack:** Existing TypeScript/React, Postgres/RLS, Supabase Edge Functions and Node/local integration tests. No LLM or geocoding API is required.

**Spec:** [Launch-readiness design](../specs/2026-10-01-launch-readiness-design.md), especially section 4.5. Proposed; no data activation is approved by this plan.

## Global Constraints

- Preserve unrelated dirty files and private research; never deploy the checkout wholesale.
- No hosted writes, external sends, paid services, push or deployment without explicit release scope.
- Never put patient content or credentials in URL paths/queries, analytics, logs or browser persistence; only the existing short-lived auth fragment flow may carry link credentials, which must be scrubbed.
- Keep public signup disabled and the current recipient restriction until an approved pilot expansion.
- Never import candidates as active or infer identity, registration, funding or availability from scraping.
- Server-side membership, participant and credential checks remain authoritative; the UI is not an access boundary.
- Preserve stable request IDs, server consent timestamps, optimistic versions and append-only audit events.
- Keep the current React/Vinext/Supabase stack initially; pin dependency changes and test both build targets.
- Keep charcoal/red, native system fonts and the existing Hugeicons adapter; no new icon library or visual rebrand.
- Distinguish saved, queued, sent, delivered, accepted and externally arranged outcomes everywhere.

## Review Focus

- Non-AHPRA profession with absent protocol: B1/B2 keeps it unselectable, never forces a fake AHPRA number.
- Expired credentials or changed practice data after shortlist: B2/B3 revalidates at finalisation and preserves history.
- Unknown location, real 0km and multiple locations: B5 distinguishes them and labels approximation.
- Access notes, aliases and unsupported funding: B4 treats them deliberately, without substring/clinical inference.
- Duplicate names, 5,000 rows and forged cursors: B6 remains bounded, stable and authorisation-filtered.

## File map and contract rules

New pure modules: `app/lib/professions.ts`, `app/lib/terminology.ts`,
`app/lib/credentials.ts`, `app/lib/geography.ts`, `app/lib/directory.ts`.
Backend copies of enums are prohibited: use a checked-in, versioned JSON
catalogue readable by Node/browser/Deno and a reviewed migration/seed generator
for database rows. Database catalogue rows are authoritative for activation.
Source catalogues contain no people/contact records. Source candidate exports
remain outside deployable assets.

New migrations are generated by CLI at execution, never backdated. B2 is
expand/validate/contract: legacy readers remain safe until all consumers migrate.

**Dependencies:** B4/B5 (geography may remain explicitly disabled). **Files:**

`tests/directory-query.test.mjs`, `tests/browser/directory-scale.spec.ts`;

**Interfaces:** `searchPractitioners(client,{needs,postcode?,radiusKm?,
distanceGroup:'local'|'unknown'|'remote',cursor?,limit?:number}):
Promise<{items:MatchResult[],nextCursor:string|null,totalEligible:number,
groupCounts:{local:number,unknown:number,remote:number}}>`; default limit 25, hard

Telehealth-only searches use the remote group for all eligible telehealth providers.

disable radius rather than dropping them. Counts and cursors share the same
authorised needs/filter snapshot; switching group resets the cursor.
`listReferralPage(client,{organisationId,status?,
search?,cursor?,limit?}): Promise<{items:Referral[],nextCursor,counts}>` with the
same limits; counts cover authorised filtered scope, not fetched-page length.
