# Privacy and release operations — blocked for clinical use

Current mode is private_test. Existing privacy/terms remain explicitly draft; `/support` uses the existing test-organiser address and promises no monitored pilot service or response time. Support links have no clinical subject/body or automatic attachments.

`release-evidence.ts` holds null evidence references. `RELEASE_MODE=pilot` or an unknown mode blocks builds and workflow requests. Environment flags alone cannot approve notices/business identity. Record actual founder/legal/clinical approvals and publish their reviewed notices before changing this source-controlled evidence. Do not copy fictional test values into it.

Email requires delivery enabled, valid trust configuration, an explicit nonempty exact-recipient allowlist (also for the bounded pilot), and no restore quarantine. The prior empty-allowlist unrestricted behaviour is removed. This is a transport limit, not consent evidence or permission for bulk acquisition.

Before pilot approval, assign real owners and evidence for business identity/support, privacy/terms versions, contact/acquisition basis, external handover protocol, retention/legal holds, recovery, monitoring, Auth abuse protection and actual mailbox journeys. Obtain qualified Australian/NSW review; code cannot supply legal authority.

Requests: authenticate the requester independently, establish practice/record authority, identify active records plus processors/backups, record the request in an approved private case system, agree the permitted access/export/correction/redaction action and obtain approval before executing. Do not email patient content or delete `auth.users` as a blanket erasure procedure. Preserve required audit/holds; explain backup/processor limitations. Accidental real data in this test: stop use, restrict access, notify the approved owner through the established private channel and follow the incident process.
